# Исправления пайплайна создания и просмотра вечеринок

## Проблемы, которые были исправлены

### 1. ❌ Веб-приложение не читало параметр `party` из URL
**Проблема:** `App.tsx` всегда показывал демо-режим, игнорируя параметр `?party=XXX` из URL.

**Исправление:**
- Добавлено извлечение `shortCode` из query параметра `party`
- Если параметр есть - загружается конкретная вечеринка
- Если параметра нет - показывается демо (первый плейлист)

### 2. ❌ Отсутствовал эндпоинт для получения информации о вечеринке
**Проблема:** На сервере не было эндпоинта `GET /api/parties/public/{shortCode}` для получения информации о вечеринке (название, стиль).

**Исправление:**
- Добавлен эндпоинт `GET /api/parties/public/{shortCode}` в `PublicPartiesController`
- Создана модель `PublicPartyDto` на сервере
- Добавлено поле `CustomizationSettings` в модель `Party`
- При создании вечеринки теперь сохраняются настройки кастомизации

### 3. ❌ Веб-приложение не отображало название вечеринки
**Проблема:** Название вечеринки не показывалось на странице.

**Исправление:**
- Добавлена загрузка информации о вечеринке при наличии `shortCode`
- Название вечеринки отображается в заголовке страницы
- Применяется правильный стиль (themeId) из настроек вечеринки

## Как теперь работает пайплайн

### 1. Создание вечеринки (CherryPlayList)
1. Пользователь создает вечеринку в приложении
2. Приложение отправляет POST запрос на `/api/parties`
3. Сервер создает вечеринку с уникальным `shortCode`
4. Сервер возвращает `PartyDto` с `shortCode`
5. Приложение генерирует URL: `http://localhost:3000/?party={shortCode}`
6. Пользователь копирует URL

### 2. Просмотр вечеринки (CherryPlayWeb)
1. Пользователь открывает URL: `http://localhost:3000/?party=ABC123`
2. `App.tsx` извлекает `shortCode` из параметра `party`
3. `PartyView` загружает плейлист через `/api/parties/public/{shortCode}/playlist`
4. `PartyView` загружает информацию о вечеринке через `/api/parties/public/{shortCode}`
5. Применяется стиль из настроек вечеринки
6. Отображается название вечеринки и плейлист

### 3. Демо-режим
1. Пользователь открывает `http://localhost:3000` (без параметров)
2. `App.tsx` не находит параметр `party`
3. `PartyView` работает в демо-режиме
4. Загружается первый доступный плейлист через `/api/parties/public/first`

## Измененные файлы

### CherryPlayWeb
- `src/App.tsx` - добавлено извлечение `shortCode` из URL
- `src/pages/PartyView.tsx` - добавлена загрузка информации о вечеринке и отображение названия

### CherryPlayServer
- `Controllers/PublicPartiesController.cs` - добавлен эндпоинт `GET /api/parties/public/{shortCode}`
- `Models/Party.cs` - добавлено поле `CustomizationSettings`
- `Models/PublicPartyDto.cs` - создана новая модель
- `Controllers/PartiesController.cs` - сохранение `CustomizationSettings` при создании

## Тестирование

1. **Создайте вечеринку в приложении:**
   - Откройте CherryPlayList
   - Создайте вечеринку
   - Скопируйте URL

2. **Откройте URL в браузере:**
   - Должен загрузиться плейлист конкретной вечеринки
   - Должно отображаться название вечеринки
   - Должен применяться правильный стиль

3. **Проверьте демо-режим:**
   - Откройте `http://localhost:3000` без параметров
   - Должен загрузиться первый доступный плейлист
   - Должен отображаться бейдж "Демо режим"

## API Endpoints

### Работающие эндпоинты:
- ✅ `GET /api/parties/public/first` - первый плейлист (демо)
- ✅ `GET /api/parties/public/{shortCode}` - информация о вечеринке
- ✅ `GET /api/parties/public/{shortCode}/playlist` - плейлист вечеринки
- ✅ `POST /api/parties` - создание вечеринки

### Планируемые (для будущей реализации):
- ⏳ `GET /api/parties/public/{shortCode}/state` - состояние вечеринки (для SignalR)
