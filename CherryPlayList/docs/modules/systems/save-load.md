# Save / Load

Система сохранения и загрузки проектов CherryPlayList.

## Описание

Проект сохраняется в файл формата `.cherry` (JSON) и загружается из него. Все операции с файловой системой выполняются через IPC в Electron main process; renderer process обращается к ним через `ipcService`.

Это **отдельный** канал от автоматического **клиентского persist** (IndexedDB через Zustand) — см. [Storage](./storage.md), [архитектура](./storage-architecture.md), [что храним в persist](./persisted-client-state.md).

## Основные компоненты

- **projectService** (`src/shared/services/projectService.ts`) — сериализация/десериализация, загрузка с разрешением путей и проверкой доступности треков, сохранение с поддержкой портативного режима
- **IPC handlers** (`electron/ipc/project.ts`) — обработчики `project:save`, `project:savePortableAs` и `project:load` в main process; реализует копирование треков при портативном режиме
- **projectStore** (`src/shared/stores/projectStore.ts`) — хранит данные проекта и `meta.filePath`; действие `setPortableMode` управляет флагом портативного режима
- **AppHeader** (`src/app/components/AppHeader.tsx`) — верхний ряд шапки: слева **меню «Файл»** (иконка **⋮**, `aria-label` / `title` **«Файл»**); справа **Аккаунт** (при включённом **Онлайн**) и **Настройки**. Меню **Файл**: **Новый проект**, **Открыть проект…**, **Экспорт**, **Сохранить проект**, **Сохранить как…**; в web demo / fixtures — **Учебный демо-проект…** (`title` «Загружает учебный демо-проект, не настоящую вечеринку»). Party-status, playback pill и **WorkspaceMenu** — в нижнем ряду шапки (см. [party.md — Шапка](../workspaces/party.md#шапка-appheader-статус-и-пульт)). Пока нет `meta.filePath`, **«Сохранить как…»** скрыт; **«Сохранить проект»** открывает первое сохранение. **SaveProjectAsModal** — диалог **Сохранить как…**. Во время сохранения — спиннер на триггере меню; пункты дизейблятся.

### Несохранённые изменения (`meta.isDirty`)

Перед **Новый проект**, **Открыть проект…** и **Учебный демо-проект…** при `meta.isDirty === true` показывается стилизованный диалог приложения: «В проекте есть несохранённые изменения. Продолжить и отбросить их?» — отмена оставляет текущий проект. Подтверждения и предупреждения приложения открываются через `dialogService` и `DialogHost`; нативными остаются системные окна выбора файлов и папок.

## Формат файла `.cherry`

JSON-файл версии `2.1`. Содержит прежние поля проекта и:

- `version` — версия формата
- `name` — название проекта
- `items` — плоский список треков и групп (с полем `path` для треков)
- `rootItems` — ID корневых элементов
- `settings` — настройки проекта, включая `portableMode`
- `trackSettings`, `groupSettings` — настройки отдельных элементов
- `sessionState` — состояние сессии
- `linkedParty` — привязанная вечеринка (опционально)
- `partyTrackDisplay` — настройки отображения имён треков для вечеринки; записываются при сохранении, а при отсутствии в старом файле используются значения по умолчанию
- `partyThemeId` — черновик/кэш темы вечеринки (опционально)
- `partyCustomizationSettings` — черновик/кэш настроек кастомизации темы, включая `groupDisplayDepth`, локальный JSON (опционально)
- `collections` — массив `{ id, name, items, rootItems }` для всех подборок проекта, включая закрытые окна и пустые списки
- `collectionViewState.bindings` — сохранённые привязки `workspaceId` к `collectionId` (опционально; используются при восстановлении соответствующих зон; привязки удалённой подборки удаляются вместе с ней)

Файл `.cherry` хранит копию этих полей вместе с остальным meta для переноса проекта между машинами и сессиями. Для **опубликованной** вечеринки каноническое состояние темы и оформления задаёт **сервер** (ответы API с `partyThemeId` и `customizationSettings`). После открытия `.cherry` при наличии сети клиент подтягивает актуальные данные с API и согласует локальное состояние — подробнее см. [Клиентское состояние: что храним](./persisted-client-state.md) (подраздел про сервер и кэш).

## Портативный режим

### Что делает

При включённом `portableMode` сохранение проекта дополнительно:

1. Копирует треки основного плейлиста в `tracks/`, а треки каждой подборки — в отдельную папку `collections/<имя>/`. При совпадении безопасных имён добавляется числовой суффикс.
2. Заменяет пути в сохраняемом файле относительными к `.cherry` файлу.

Это позволяет перенести папку с `.cherry` файлом, `tracks/` и `collections/` на другой компьютер и сразу открыть проект без сломанных путей.

### Как включить переносимую копию (основной сценарий)

**Сохранить как…** в меню **Файл** (иконка **⋮**) открывает единый диалог: имя проекта + папка назначения + чекбокс **«Переносимый проект»** (краткое пояснение и иконка с подсказкой в том же диалоге). Это не отдельный пункт верхнего меню, а опция **внутри** **Сохранить как…**.

Отдельного чекбокса переносимого режима в модалке **настроек** **нет**. В разделе **«Настройки проекта»** — текстовая подсказка: переносимая копия включается через **Файл** → **Сохранить как…** → **«Переносимый проект»**; обычное **Сохранить проект** сохраняет флаг `portableMode` из уже открытого `.cherry`. См. [Settings Store](../stores/settings-store.md).

### Поведение при сохранении

В диалоге **Сохранить как…** пользователь выбирает **папку назначения** и задаёт **имя проекта**:

- **обычный режим (чекбокс выключен)**: создаётся файл **`<папка>/<имя>.cherry`**;
- **переносимый режим (чекбокс включен)**: создаётся каталог **`<папка>/<имя>/`**, внутри — **`<имя>.cherry`**, `tracks/` и папки подборок в `collections/`.

Для переносимого режима действует strict-семантика: копируются **все** треки; при любой ошибке (нет пути к файлу, нет доступа к источнику, сбой копирования) **вся** операция **прерывается**.

- Треки, уже лежащие в `tracks/`, не копируются повторно; путь переписывается в относительный.
- При конфликте имён добавляется числовой суффикс: `track_2.mp3`, `track_3.mp3` и т.д.
- ID подборки хранится в `.cherry`; имя папки содержит только безопасное имя подборки. При переименовании папки вручную относительные пути к трекам перестают работать, поэтому загрузка переносимого проекта завершится ошибкой с указанием проверить имя папки и целостность пакета. Совпадения безопасных имён подборок получают числовой суффикс. Совпадения имён аудиофайлов разрешаются числовыми суффиксами внутри целевой папки.
- При обычном сохранении переносимого проекта устаревшие копии удаляются только после успешного сохранения нового `.cherry`; учёт включает основной плейлист и все подборки.
- Main process шлёт в окно `project:save-progress` (`{ current, total, fileName }`) на каждый копируемый трек (канал разрешён в preload); **отдельной индикации прогресса по файлам в UI нет** — только спиннер в меню **Файл** (см. «Индикация сохранения»). В `.cherry` при успешном переносимом сохранении `settings.portableMode` = `true`.

### После успешного сохранения

Успешное **Сохранить** / **Сохранить как…** (в т.ч. переносимый пакет) **без toast**: диалог закрывается (если был открыт), спиннер в меню пропадает, `meta.filePath` и dirty-флаг обновляются. Toast показывается только при **ошибке** сохранения (или при blocked-feature на платформе без project persistence — `warning`).

### Индикация сохранения

Во время операции в шапке на триггере меню **Файл** (иконка **⋮**) показывается спиннер, команды меню блокируются до завершения. Успех подтверждается исчезновением спиннера и обновлением UI, не отдельным уведомлением.

### Поведение при загрузке

При открытии `.cherry` файла `loadProject` в `projectService`:

1. Проверяет версию `2.0` или `2.1`; в файлах `2.0` подборки и привязки загружаются как пустые.
2. Обнаруживает относительные пути (начинаются с `./` или `../`), в том числе пути файлов подборок.
3. Разрешает их в абсолютные относительно папки файла проекта.
4. Проверяет доступность каждого файла через `ipcService.statFile`.
5. Если файл недоступен — устанавливает `track.isMissing = true`; элемент подборки остаётся в проекте.

В памяти пути **всегда абсолютные**. Относительные пути существуют только на диске в `.cherry` файле.

### Предупреждения о недоступных треках

Треки с `isMissing: true` отображаются с иконкой `⚠` в строке плейлиста. Tooltip показывает путь файла.

## IPC-события

| Событие                  | Направление     | Данные                                                                                   |
| ------------------------ | --------------- | ---------------------------------------------------------------------------------------- |
| `project:save`           | renderer → main | `{ path, projectFile, portableMode? }`                                                   |
| `project:savePortableAs` | renderer → main | `{ parentPath, projectFile }` — переносимый пакет в `parentPath/<имя проекта>/` (strict) |
| `project:load`           | renderer → main | `{ path }`                                                                               |
| `project:save-progress`  | main → renderer | `{ current, total, fileName }`                                                           |

В зависимости от сценария вызова обработчик может принимать в payload дополнительные необязательные поля (например, `strictSourceFiles`).

## Валидация при загрузке

- Проверка версии формата (`2.0` и `2.1`; новые сохранения используют `2.1`)
- Проверка обязательных полей (`name`, `items`, `rootItems`, `settings`)
- Проверка ссылочной целостности (все ID существуют)
- Для подборок проверяются уникальность ID, структура элементов и ссылки на корневые элементы; некорректные привязки окон удаляются при нормализации.
- Валидация `portableMode` (должен быть boolean, иначе используется default `false`)
