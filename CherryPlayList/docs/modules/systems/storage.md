## Кратко: зачем не «голый» localStorage

- **`localStorage`** в Electron может терять данные при спящем режиме или аварийном завершении
- синхронный API и ограничение объёма (~5–10 МБ)
- **localforage** с приоритетом **IndexedDB** даёт асинхронность, больший объём и устойчивее поведение для крупных объектов

## Преимущества localforage (как используется здесь)

- **Асинхронное хранение** — не блокирует UI
- **Надёжнее** для типичных сценариев сохранения на диск
- **Больший практический объём** (ограничения движка)
- **Выбор драйвера:** IndexedDB → WebSQL → localStorage

Все сторы, подключённые к `persist` с `storage: electronStorage`, проходят через один instance localforage с базой **`CherryPlayList`** и хранилищем **`app-storage`**.
