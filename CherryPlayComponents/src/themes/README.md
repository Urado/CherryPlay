# PartyTheme (темы вечеринок)

Система **PartyTheme** для CherryPlay Components: визуальный стиль контента вечеринки (плейлист, текущий трек, страница info). Не путать с темой оболочки приложения (тёмная/светлая). См. [GLOSSARY.md](../../GLOSSARY.md).

Продуктовый default: константа `DEFAULT_PARTY_THEME_ID` (`'basic'`) из `@cherryplay/components` / `partyThemeTypes.ts`.

## Доступные PartyTheme

### Cyberpunk

Неоновая тема в стиле киберпанк с зелеными акцентами и эффектами свечения.

Настройки кастомизации отсутствуют (используется `CustomizationEditor`, который возвращает `null`).

### Sakura

Нежная пастельная тема с розовыми оттенками.

Настройки кастомизации отсутствуют (используется `CustomizationEditor`, который возвращает `null`).

### Art Deco

Элегантная тема в стиле ар-деко с золотыми акцентами и геометрическими паттернами.

Настройки кастомизации отсутствуют (используется `CustomizationEditor`, который возвращает `null`).

### Basic

Базовая тема без дополнительных декоративных эффектов.

## Группы в плейлисте

В текущей базовой реализации для тем **Basic**, **Cyberpunk**, **Sakura** и **Art Deco** заголовки групп отличаются от строк треков и показывают сводку: число доступных треков, прогресс в формате «сыграно X из N» и суммарную длительность. Отменённые треки не входят в число и прогресс; треки внутри отменённой группы также исключаются. Длительность группы показывается, только если она известна у каждого подходящего неотменённого трека; если хотя бы у одного такого трека длительность неизвестна, длительность всей группы скрывается. Исключение отменённых треков из расчёта длительности описывает текущее поведение реализации и ещё требует подтверждения как продуктовое правило. Отменённая группа и её содержимое остаются видимыми с состоянием отмены.

Группы всегда раскрыты. Группы не нумеруются; номера треков образуют сквозную последовательность в порядке отображения. Отменённые треки пропускаются при нумерации.

В теме **Basic** каждая группа объединяет заголовок и содержимое общей мягкой рамкой. Вложенность передаётся отступами контейнеров без соединительных линий дерева; заголовок не занимает пустое место под номер трека. На узких экранах сводка группы переносится под название, а отступы уменьшаются.

Максимальная отображаемая глубина задаётся `customizationSettings.groupDisplayDepth` (целое от 0 до 10, значение по умолчанию — `3`). Если цепочка вложенных групп глубже выбранного значения, верхние заголовки скрываются, а их непосредственные дочерние элементы поднимаются на освободившийся уровень с сохранением порядка. Например, при глубине 3 цепочка `Группа 1 → Группа 2 → Группа 3 → Группа 4 → Трек 1` отображается как `Группа 2 → Группа 3 → Группа 4 → Трек 1`. Значение 0 скрывает все заголовки, сохраняя треки и их порядок. В ветках со смешанными группами и прямыми треками элементы скрытых групп также поднимаются с сохранением общего порядка.

Настройка глубины доступна в панели «Отображение» превью. Тема **«Весенний кросс-степ»** сохраняет собственную текущую отрисовку групп; управление глубиной к ней не применяется и в панели недоступно. Общая статистика и правила нумерации выше описывают четыре темы с общей базовой отрисовкой, а не Spring.

### Весенний кросс-степ (spring-cross-step)

Светлая весенняя тема с зелёными акцентами. Тема переопределяет **CurrentTrackDisplay** и **PlaylistView**.

**CurrentTrackDisplay:** помимо блока «Сейчас играет» показываются опциональные строки «Предыдущий» (выше) и «Следующий» (ниже). Порядок — плоский плейлист (только треки, по display order; группы игнорируются). Предыдущий/следующий отображаются только при наличии и при более чем одном треке в плейлисте. Строки выровнены по правому краю, без разделительных линий и отступов (margin/padding) между ними и текущим блоком. Длительность трека выводится в одной строке с названием; при раскрытии названия длительность остаётся по центру по вертикали. Строки стилизованы менее заметно (меньше, прозрачнее); текущий блок остаётся в фокусе.

**PlaylistView:** в строке статуса показывается только количество ещё не сыгранных треков (без учёта отменённых и текущего): надпись «Осталось треков:» и жирное число; если осталось 0 или 1 трек — «Последний трек»; если сессия завершена (`isSessionActive === false`), в плейлисте были треки и оставшихся 0 — «Вечеринка окончена». Пустой плейлист (0 треков) не показывает «Вечеринка окончена» — остаётся «Осталось треков: 0». Нумерация треков в списке не учитывает отменённые (отменённые пропускаются в счёте); у групп в кружке номер не отображается. На узких экранах (≤480px) надпись может переноситься на две строки, блок статуса выравнивается по центру.

**Названия треков:** по умолчанию в одну строку; при обрезке в конце строки показывается кликабельное многоточие (…), по клику название разворачивается в несколько строк, по клику по «×» — сворачивается. Если название полностью помещается в строку, кнопок нет. Отображаемое имя — из `name` с отрезанием только последнего расширения файла (`stripLastExtension`, `src/core/utils/string.ts`). Обрезка определяется через хук `useIsTruncated` (`src/core/hooks/useIsTruncated.ts`); порядок треков — `getFlatTracksInDisplayOrder` из `src/core/utils/playlist.ts`.

## Отображение названия и подзаголовка

В данных вечеринки используются поля:

- **Название (name)** — обязательное, для каталога и настроек.
- **Заголовок (title)** — необязательный; на экране отображается как **title ?? name** (если заголовок пуст, показывается название).
- **Подзаголовок (subtitle)** — необязательная строка под заголовком.

## Исключённые треки

Исключённый из проигрывания трек отображается отдельно от сыгранного: в общей базовой реализации и теме Art Deco в круглом красном индикаторе показывается значок Stop; название зачёркивается красной линией. В теме «Весенний кросс-степ» используется крестик на приглушённом красном индикаторе; наведение или активация значка показывает пояснение **«Трек отменён»**. Состояние исключения задаётся через `disabledTrackIds` / `disabledGroupIds` и не меняет порядок плейлиста.

## PartyDisplay и PartyInfoDisplay: плавающие декорации

Темы, которые поддерживают плавающие декорации (например, падающие лепестки в spring-cross-step), показывают их всегда. Контейнер лепестков ограничен областью компонента (`.party-display` с `position: relative`), поэтому в превью в приложении организатора лепестки остаются в зоне превью, а на полноэкранной странице вечеринки — в зоне страницы.

## Использование

```typescript
import { PlaylistView, applyPartyTheme, PartyThemeId } from '@cherryplay/components';

// Применить PartyTheme к компоненту (в API поле partyThemeId)
<PlaylistView
  playlist={playlistData}
  themeId="basic"
/>

// Или применить PartyTheme программно
applyPartyTheme('sakura', element);
```

## Структура

Каждая PartyTheme находится в отдельной папке:

- `cyberpunk/` — стили для PartyTheme Cyberpunk
- `sakura/` — стили для PartyTheme Sakura
- `art-deco/` — стили для PartyTheme Art Deco

Каждая папка содержит:

- `playlist.css` — стили для PlaylistView
- `playlist-item.css` — стили для PlaylistItem
- `player.css` — стили для CurrentTrackDisplay
- `index.css` — главный файл, импортирующий все стили и определяющий CSS переменные
- `CustomizationEditor.tsx` — UI-редактор настроек темы (часть контракта темы); для тем без настроек возвращает `null`

## CSS переменные

Каждая PartyTheme определяет свои CSS переменные через атрибут `data-theme`:

- `--bg-primary`, `--bg-secondary`, `--bg-tertiary` - цвета фона
- `--text-primary`, `--text-secondary`, `--text-tertiary` - цвета текста
- `--accent-primary` - цвет акцента
- `--border-color` - цвет границ

Оболочка PartyTheme должна быть локальным элементом компонента или страницы. `applyPartyTheme` требует явный целевой элемент и не меняет `document.documentElement`. Общие примитивы внутри PartyTheme читают переменные этой темы, включая границы, состояния и текст на акценте. Если themed UI использует портал в `document.body`, сохраните атрибут `data-theme` на обёртке портального содержимого. Тема `spring-cross-step` уже делает это для подсказки отменённого трека.
